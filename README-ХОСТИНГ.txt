VOIDFAST — САЙТ ДЛЯ ХОСТИНГА
=================================

Что лежит в папке hosting
-------------------------
  *.html              семь страниц сайта (index, about, security, install,
                      alpha, site, terms) и 404.html
  assets\             стили, скрипт, картинки и иконки
  download\           сюда положить VoidSetup.exe; рядом уже лежит
                      VoidSetup.exe.sha256 — контрольная сумма файла
  .htaccess           защита и заголовки для Apache (обычный хостинг с cPanel)
  _headers            то же для Netlify / Cloudflare Pages
  nginx-snippet.conf  то же для своего сервера на nginx
  robots.txt          правила для поисковиков
  sitemap.xml         карта сайта (адрес подставляется ключом --domain)

Как выложить
------------
1) Обычный хостинг (cPanel, FTP, FileZilla):
   * подключитесь по FTP/SFTP к папке сайта (обычно public_html или www);
   * загрузите ВСЁ содержимое папки hosting, включая скрытый файл .htaccess
     (в FileZilla включите показ скрытых файлов: Сервер -> Показывать скрытые);
   * в панели хостинга включите бесплатный SSL (Let's Encrypt);
   * положите установщик в папку download\ (см. ниже);
   * откройте https://ваш-домен/ и проверьте страницы.

2) Netlify или Cloudflare Pages (без FTP, просто перетащить папку):
   * создайте новый проект и перетащите папку hosting в окно загрузки;
   * файл .htaccess там не работает, но _headers работает — он уже внутри.

3) Свой сервер (VPS, nginx):
   * скопируйте папку в /var/www/voidfast;
   * вставьте содержимое nginx-snippet.conf в свой server { };
   * перезапустите nginx и включите сертификат (certbot).

Где это разместить (важно: установщик 103,7 МБ)
--------------------------------------------------------
Не всякий бесплатный хостинг примет файл на сотни мегабайт. Проверенные
варианты на 2026 год:

  1. Beget — бесплатный хостинг: 1 ГБ, 25 000 файлов, один сайт, Apache,
     .htaccess работает как есть, бесплатный SSL. Установщик занимает
     примерно четверть места — влезает. Плюс: русский, без VPN, панель
     на русском. Платный тариф (от 420 руб./мес) — 12 ГБ и безлимитный
     трафик, если скачиваний станет много.
  2. GitHub Pages + GitHub Releases — бесплатно и без лимита трафика:
     сам сайт в репозиторий (до 1 ГБ), а установщик — в раздел Releases
     (файл до 2 ГБ, загружается через браузер). Минус: на GitHub Pages
     НЕ работают свои заголовки (.htaccess/_headers), поэтому останется
     только CSP из <meta> — защита слабее, чем на обычном хостинге.
  3. Cloudflare Pages + Cloudflare R2 — бесплатно, _headers работает:
     сайт на Pages (но файл на странице не больше 25 МБ, поэтому
     установщик кладём в R2 — 10 ГБ хранилища, трафик не считается),
     и в HTML ставим ссылку на файл из R2.
  4. Netlify — сайт разместит, _headers работает, но на бесплатном тарифе
     около 15 ГБ трафика в месяц: это всего ~50 скачиваний установщика.
     Для самого сайта годится, для файла — нет.
  5. VPS (Timeweb, Reg.ru и т.п.) — полный контроль, но нужно самому
     настроить nginx; подойдёт, если вы умеете.

Коротко: проще всего обычный хостинг с Apache и хотя бы 1-2 ГБ места
(Beget и подобные) — тогда папку hosting можно залить целиком вместе
с файлом download\VoidSetup.exe, и больше ничего настраивать не нужно.

Установщик
----------
Файл VoidSetup.exe весит 103,7 МБ. Ссылки на сайте ведут на
/download/VoidSetup.exe, поэтому положите файл в папку download под этим именем.
Рядом уже лежит VoidSetup.exe.sha256 — это контрольная сумма файла, она
публикуется на странице install.html, чтобы посетитель мог проверить, что
скачал именно наш установщик. Если пересобираете VoidSetup.exe — заново
запустите build_hosting.py, чтобы хеш на сайте обновился.
Если хостинг не принимает такие большие файлы или не даёт столько места:
  * загрузите установщик на Яндекс Диск, Google Drive, в Cloudflare R2 или
    в GitHub Releases;
  * получите прямую ссылку на скачивание;
  * пересоберите сайт с этой ссылкой:
    python tools\build_hosting.py --download-url "https://.../VoidSetup.exe"
  * хеш SHA-256 из install.html оставьте — он остаётся верным.

Согласие пользователя (terms.html)
----------------------------------
На странице install.html и в блоке скачивания на index.html кнопка скачивания
заблокирована, пока посетитель не поставит галочку «принимаю условия и весь риск
на себя». Сами условия — на странице terms.html (отказ от ответственности,
статус alpha, потеря данных, чужие расширения и т.д.). Меняли текст — правьте
site/terms.html и пересобирайте сайт этим скриптом.

Проверка после загрузки
-----------------------
* https://securityheaders.com — вставьте свой адрес: должно быть A или A+;
* https://www.ssllabs.com/ssltest/ — проверка сертификата;
* откройте сайт в браузере и нажмите F12 -> Console: ошибок быть не должно.

Про «шифрование» сайта — честно
-------------------------------
Полностью зашифровать HTML/CSS/JS нельзя: браузер посетителя обязан их
прочитать и выполнить, поэтому любой «шифр» расшифровывается за минуту.
Что реально защищает сайт и уже сделано здесь:

  * на сервере только статические файлы — нет PHP, нет базы данных, нет
    админки, поэтому взладывать нечего (типовые атаки вроде SQL-инъекций
    и загрузки шеллов просто не к чему применить);
  * CSS и JS сжаты и очищены от комментариев — код не читается «как книга»;
  * SRI-хеши: если кто-то подменит style.css или app.js на сервере, браузер
    откажется их загружать (это настоящая защита от подмены файлов);
  * CSP с Trusted Types: страницам разрешено выполнять только свои скрипты,
    а DOM-XSS (вставка чужого кода через innerHTML) браузер блокирует;
  * .htaccess/nginx: запрет листинга папок, запрет выполнения php/py/cgi,
    закрытые .git и бэкапы, X-Frame-Options (нельзя вставить сайт в рамку),
    HSTS и принудительный HTTPS.

Защита от «перенаправления» и сайтов-клонов
-------------------------------------------
Чужой скрипт не сможет увести посетителя с нашей страницы, потому что:

  * в CSP стоит form-action 'none' — навязанная посетителю форма уйти
    на чужой адрес не сработает; base-uri 'none' — нельзя подменить
    «базу» ссылок через <base>; frame-ancestors 'none' и X-Frame-Options —
    сайт нельзя вставить в рамку и наложить на него чужие ссылки
    (классическая уловка «кликджекинг»);
  * frame-src 'none' и object-src 'none' — внутри страницы не загрузится
    посторонняя рамка или плагин;
  * в _headers есть Content-Disposition: attachment для /download/ —
    вместо запуска файла в браузере он просто скачивается;
  * в .htaccess есть (закомментированное) правило «отдавать сайт только по
    своему домену»: включите его, когда сайт уже открывается по своему
    адресу, — тогда чужой домен, направленный на этот хостинг, получит 403;
  * canonical-ссылка и og-теги (появляются при сборке с ключом --domain)
    говорят поисковикам и мессенджерам, что настоящий адрес — ваш, а не
    копия сайта на чужом домене.

Чего технически сделать нельзя (и обещать не будем): поставить «шифр»,
который помешает мошеннику скопировать страницу на свой адрес. Копию
сайта можно отличить только двумя способами — по адресу в строке браузера
и по контрольной сумме файла. Оба способа уже объяснены посетителю на
странице install.html, а хеш подставлен туда автоматически.

Что нужно сделать вам (это важнее любых «шифров»):
  1. пароль на хостинг — длинный и уникальный, включите двухфакторную защиту;
  2. не храните на хостинге резервные копии и старые файлы;
  3. включите автоматическое обновление/бэкапы в панели хостинга;
  4. не выкладывайте папку проекта целиком — только папку hosting.
